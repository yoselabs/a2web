# API surface

Covers `src/a2web/routers.py`, `models.py`, and `fetcher_response.py` — the
tool signatures, the response models, and the module that builds one from the
other.

- `src/a2web/routers.py` — `register_web_tools(mcp, components)` and `register_cookies_tools(mcp, components)`. Tools are plain closures over `Components`, registered with `@mcp.tool(name=..., annotations=ToolAnnotations(...), tags=...)`. **The parameter list IS the wire schema** (design D1) — there is no wire/injected partition to guess, and no registration elsewhere can change it. `query(url, query, ...)` is primary (renamed from `ask(url, question)` in v0.23 / ADR-0015; runs server-side LLM extraction, returns the lean `AskResponse`); `fetch_raw(url, ...)` is the fallback (no LLM, page-shaped `FetchResponse`). Both delegate to `fetcher.fetch`; `query` projects via `build_ask_response`. Resources reach the orchestrator as UNAWAITED thunks (`browser_backend=components.browser_backend`) — awaiting one here would silently kill cold start. Tool args use `Annotated[T, pydantic.Field(description=...)]`. Phases emit via `await a2web.log.info(...)` and never receive ctx.
- `src/a2web/models.py` — `FetchResponse` (page-shaped, returned by `fetch_raw`), `AskResponse` + `AskExtraction` (the lean `query` envelope — drops `content_md`/`headings`/`tokens`, omits empty optionals via a `@model_serializer`. Field tiers: failure-only `status`/`narrative`/`diagnostics_summary` (absent on success — absence of `status` means ok); debug-only `extraction`/timing/`cache`/`diagnostics`. `other_pages` renders as a TSV block, not a JSON array; truncation surfaces as an `answer_truncated` operator hint, never an `extraction: {truncated}` object). **Router-shape on `AskResponse` (v0.23 / ADR-0015):** `answer` (always) + conditionals via `_prune_wire` (`obstacle` Literal-4, `also_here: list[str]` — the same-page index in query grammar, `other_pages: list[OtherPage]` — kind-tagged `structural`|`drilldown`, unifying the former `next_links` + `try_url`) — conditionals omitted from the wire when empty/null. **`declared_entity: DeclaredEntity | None` (2026-08-03 / ADR-0018)** carries what the PAGE declared itself to be, parsed from its own JSON-LD and never inferred: `type` verbatim as a LABEL (no allowlist), `source: "declared"` so a caller never guesses whether a2web read it or wrote it, `fields` capped at `DECLARED_FIELDS_CAP = 20`, `omitted` counting the remainder. **Both numbers are measured, not chosen** — `declared_entity_v4` (+0.095 coverage on declaring pages, CI [+0.010, +0.180], indistinguishable from an LLM-generated block costing ~161 tokens at 58% type stability) and `declared_cap_v5` (the knee: cap 10 vs 20 is a significant loss, cap 20 vs uncapped is null while the wire cost doubles). A PrivateAttr on `FetchResponse` — `fetch_raw` already ships the rendered entity inside `content_md` and must not send the same facts twice. Document types (`Article`/`WebPage`/…) are held back by a BLOCKLIST, not an allowlist: an unrecognised type falls through and is surfaced. `FetchResponse` (`fetch_raw`) keeps its own `next_links: list[NextLink]`; the `other_pages` fold is scoped to the `query` envelope. `RouterPayload` pydantic mirrors the package-side `RouterPayload` boundary; closed-enum violations at the seam (`fetcher_response._project_routing`) drop the 7 fields but `answer` survives. Plus `Diagnostic`, `Verdict`, `Heading` (serializes as a compact `[level, text]` tuple), `Link`, `OperatorHint`, `TokenCounts`. Both `AskResponse` and `FetchResponse` carry a wire-only `@model_serializer` that delegates to the shared `_prune_wire(data, *, required, tsv, deviation, failure_only, debug_fields)` helper — one omit-empty + TSV + deviation + debug-regroup implementation, two thin serializers parameterized per envelope. Field tiers (v0.14 `envelope-deviation-trim`): always-present `confidence` (+ `answer` on ask); deviation-only `status` (dropped when `ok`), `tier` (dropped when `raw`), `url` (dropped when it equals the requested URL — builder-gated in `build_response` against `FetchContext.requested_url`); failure-only `narrative`/`diagnostics_summary`; debug-only `started_at`/`total_ms`/`cache`/`tokens`/`diagnostics`/`extraction` — these stay flat fields on the model but the serializer **regroups them into a wire-only nested `debug` object** (present only under `debug=True`). `links` + `next_links`/`other_pages` render as TSV. The serializer is wire-only — attribute access is unaffected, so `fetch()`'s internal callers (eval harness, `build_ask_response`) keep reading `.cache`/`.extraction`/etc. flat. `original_url` was removed in v0.14 — the surviving `url` (when present) is the deviation. All at module scope (a2kit antipattern #2). pydantic at boundaries; `dataclass(slots=True)` internally. `FetchResponse.fit_md` / `is_user_authored` were removed in v0.11 — never reintroduce a field that is provably always `None`/constant. **`NEXT_LINKS_CAP` lives here** — the `link-discovery` spec states one "capped at 10" invariant and it had SIX implementations, one of them `discourse._MAX_TOPICS = 50`, which shipped five times the cap while `handler_probe.py` recorded the violation as healthy. Pinned by `tests/architecture/test_next_links_cap_is_declared_once.py`, scoped to the function that BUILDS a `NextLink` (body-render caps live in the same files and are a different question).
- `src/a2web/fetcher_response.py` — **the response contract** (the repo's largest single module; the reason `openspec/changes/decompose-fetcher-into-files/` §7.0 exists — see there for a dated size, not here, since a raw line count drifts on every edit). Owns `build_response` (`FetchContext` → `FetchResponse`) and `build_ask_response` (→ the lean `AskResponse`), plus the link-discovery composition rules. Three things it must NOT do, each having been a real defect: **re-derive a decision from the artifact that decision produced** (it reconstructed the terminal classification three times by reading hint CODES and SEVERITIES back out, so rewording a hint could flip `retrieval_incomplete` — read `fc.terminal`, and `fc.empty_confirmed`, which are carried); **relabel a producer's own claim** (the handler→`other_pages` fold rewrote every `kind` to `structural`, false for 7 of 7 handler links, and dropped `anchor`); and **drop a page the handler found** (a handler link the LLM did not repeat was deleted outright — the LLM leads, it does not filter). Its slice of `FetchContext` is declared as the **`ResponseContext` Protocol** in that module, so `ty` checks names AND types at every call site; `tests/architecture/test_response_context_slice.py` is now only a growth budget. **Never restate the member count in prose** — a prior ledger's count went stale within the same session it was written; the Protocol replaced a name-ledger 2026-08-03 (`decompose-fetcher-into-files` §7.0) and immediately caught a defect a name-ledger structurally could not: `fc.routing` is the package-side `llm_extract.RouterPayload`, not the pydantic mirror of the same name in `models.py`.
