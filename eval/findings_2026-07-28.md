## Finding 1 — the ADR-0015 index deferral chain bottoms out into silence

> **Corrected 2026-07-28**, after pulling the trace. The first version of this
> section said the case "corroborates the 2026-07-27 `wikipedia-narrow-ask-indexes`
> finding — same invariant, different mechanism". That was too clean. The two
> share a symptom, not a cause, and the difference decides what the fix is.

On `listing-answer-always-leaves-an-index` (`arxiv.org/list/cs.CL/recent`, task
*"What are the recent NLP papers?"*), the envelope carried
`['answer', 'confidence', 'operator_hints', 'tier']` and **nothing else**. All
four index fields absent, on the one corpus case written to pin ADR-0015's
*"never withhold the body without leaving the index"*.

**Every prompt clause was followed correctly.** That is the finding:

| field | why it was empty | correct per prompt? |
|---|---|---|
| `refinement_axes` | *"OMIT on non-listings and non-selection questions"* — this is a FIND, not a selection | yes |
| `also_here` | *"on structural_form=listing DEFER to options / refinement_axes and stay sparse"* | yes |
| `other_pages` | *"zero is a VALID count — do NOT pad"*; *"if no '## page links' list is present, OMIT"* | yes |
| `options` | not an LLM field at all — DOM-parsed (`ListingOption`), and the parse found nothing | n/a |

Four independent optional fields, each with its own escape hatch, each deferring
to the others, and **no rule anywhere in the prompt that at least one must
survive**. Grepped: no such clause exists. The invariant is stated only in the
corpus criteria — a document the model never sees.

The sharpest link in the chain: **`also_here` defers to `options`, which the
model cannot emit.** `options` appears exactly once in the whole prompt, inside
that deferral clause; it is never defined as a field to produce, because it is
parsed deterministically from the DOM. So the instruction tells the model to stay
quiet because another subsystem will cover it — and the model has no way to learn
that the subsystem found nothing.

**Why this is a different defect from the Wikipedia one:**

| | `wikipedia-narrow-ask-indexes` (07-27) | this case (07-28) |
|---|---|---|
| symptom | empty `also_here` | all four index fields empty |
| cause | clause too weak — prompt v0.25 targeted exactly this and it still under-fires | clause correctly tells `also_here` to stay quiet |
| fix shape | prompt STRENGTH | prompt/envelope STRUCTURE |

Strengthening `also_here` fixes the first and does nothing for the second. Filing
them as one finding would have let a fix for one be reported as closing both.

**Open confound — resolve before shaping any fix.** The answer itself states
*"the page shows no titles, authors, or abstracts — only submission IDs and
format links"*, and the cell was served by the **browser** tier. If that render
was genuinely degenerate, the empty index is defensible and this corpus case is
measuring a RENDERING defect wearing an index defect's clothes. Probe: fetch the
same URL through the raw tier and compare what anchors and rows are available.

`reddit-listing` also produced no candidate block on either system. It fetched
`ok` via zyte, so not a wall; whether it is this defect, the Wikipedia one, or a
third thing is unresolved and should not be assumed.

**Not fixed here.** Task 8.3 of `close-silent-eval-loss` says a defect the
revived axis surfaces is recorded, not repaired inside the change that revived
it — fixing product behaviour in the same commit that fixed its measurement
would leave neither independently verifiable.

## Finding 2 — where the axis does report, the scores are mediocre

| slug | detail | extract |
|---|---|---|
| answer-carries-no-fenced-scaffolding | 5 | 5 |
| hn-front | 4 | 5 |
| gh-trending-best | 5 | 2 |
| lobste-active | 2 | 3 |
| gh-trending | 2 | 2 |
| pypi-httpx | 1 | 2 |

Mean 3.17 on both systems, over 6 scored cells each. `pypi-httpx` at 1–2 and
`gh-trending` at 2 are the weakest. **This is a first observation, not a trend** —
there is no prior measurement to compare against, because the axis has never
scored anything. Do not read the 3.17 as a regression or an improvement; it is
the first number this axis has ever produced.

`gh-trending-best` splitting 5 vs 2 between the two systems on the same page is
the most interesting single cell, since the systems differ only in envelope
shape. Worth one targeted look before drawing any conclusion from the mean.

## What this run does NOT establish

- Nothing about answer quality or clarity — both axes were deselected to keep
  the probe cheap, which is why they read `not_applicable` above.
- Nothing about the 2026-07-22 quality-0 cells. Six of those scored 0 for
  *correctly* refusing per ADR-0009 (M8 in BACKLOG); that remains open and is
  sequenced behind the corpus-schema change.
- Nothing about non-listing classes.
- Cache mode was default (cache ON), so repeat cells are not independent
  observations. `--no-extraction-cache` now exists for when that matters; the
  manifest records which mode ran.
