## Finding 1 — `other_pages` is mechanically impossible outside the raw tier

> **Twice corrected.** First filed as "corroborates `wikipedia-narrow-ask-indexes`,
> same invariant". Then as "the four index fields defer to each other and no rule
> says one must survive". Both were readings of prompt text. The probe that was
> supposed to rule out a rendering confound found the actual cause instead, and it
> is a code path, not a prompt property. The two earlier diagnoses are recorded
> here because the sequence is the point: prompt-shaped reasoning produced two
> confident, plausible, wrong answers, and one cheap probe settled it.

`listing-answer-always-leaves-an-index` (`arxiv.org/list/cs.CL/recent`) returned
an envelope of `['answer','confidence','operator_hints','tier']` — no index at
all. Probe (`include_links=True`, browser tier): 50 arXiv ids present in
`content_md`, **0 links, 0 headings**, on a page that is nothing but anchors.

```
tier ∈ {browser, jina, zyte, firecrawl, archive} or ANY of the 9 site handlers
  → TierResult.pre_rendered = Rendered(content_md, title, byline, headings)
                                         ↑ dataclass has NO links field
  → _phase_extract copies those four and RETURNS      (fetcher.py:1270-1276)
  → `fc.links = extract_result.links`  NEVER RUNS     (fetcher.py:1318)
  → fc.links == []
  → _build_link_digest: `if not fc.links: return None` (fetcher.py:2317)
  → no '## page links' block reaches the prompt
  → prompt: "If no '## page links' list is present, OMIT other_pages"
```

`other_pages` cannot be emitted on any page not served by the raw tier. Not
"tends not to be" — cannot. Only `raw` runs trafilatura, and trafilatura is the
sole producer of `fc.links`.

**This explains both failing cells with one mechanism.** arXiv came via browser;
`reddit-listing` via zyte. No coincidence required, and no need to guess whether
they were the same defect — they are.

**Scope.** Every browser/handler/archive-served page, i.e. the whole hard-fetch
population — exactly the pages where a caller most needs pointers, since those are
the ones it cannot cheaply re-fetch. ADR-0014's closed-set handle rehydration is
intact and correct throughout; it simply never receives a digest.

**The rendering confound is resolved, and it was real but not causal.** The page
genuinely did render without titles or authors (the model's answer said so
accurately). But titles are not what `other_pages` needs — anchors are, and the
anchors were lost one layer earlier, in a way that has nothing to do with arXiv.

**Not fixed here**, per task 8.3. Whether `Rendered` should carry links, or the
pre-rendered path should run link extraction over the source HTML separately, is
a design call for the change that fixes it.

# 2026-07-28 (later) — the link fix lands, and does NOT fix the target cases

**Run:** `eval/runs/post-link-fix` vs `eval/runs/axis-revival-probe`, same
invocation, same provider. 16 cells, 66 s, $0.54.

## What changed

| slug | system | before | after |
|---|---|---|---|
| listing-answer-always-leaves-an-index | both | `unscored` | **`unscored`** |
| reddit-listing | both | `unscored` | **`unscored`** |

The two cases the change was written for are unchanged. Everything else moved
within noise (`gh-trending-best` detail 5→4, `pypi-httpx` 1→0 and 2→3 — a
listing-quality axis with one prior observation ever; do not read these).

## What the change DID do — the seam is fixed and provably so

The arXiv envelope grew the fields the seam was dropping:

    before: ['answer','confidence','operator_hints','tier']
    after : ['answer','byline','confidence','operator_hints','tier','title']

and `headings` went 0 → 4 on the same page. Extraction now reaches the
orchestrator intact. On the raw HTML the canonical extractor returns **484
links** for that page, with or without `include_links` — so `fc.links` is
populated now. The seam was real and it is closed.

## Why `other_pages` is still impossible — a SECOND gate, same early return

```
_phase_extract, pre-rendered branch          (fetcher.py:1270)
  ├─ fc.links = payload.links                ← FIXED by this change
  └─ RETURN  .............................. before fetcher.py:1320:
        await _run_extraction_escalation(fc, raw_html=raw_html)
             └─ the only producer of json_synth / record_synth candidates
                
_build_link_digest                           (fetcher.py:2329)
  if not any(c.source in {"json_synth","record_synth"} for c in fc.content_candidates):
      return None                            ← still bails
```

The same early return drops **two** things. This change fixed the links half.
The candidate half means a pre-rendered page can never satisfy the digest gate,
whatever its links look like.

That gate was flagged in the change's design under Open Questions — *"even on the
raw tier a prose-shaped listing gets no digest; that one looks deliberate"* — and
left alone on the grounds that it was intentional. It is intentional for prose
pages on the raw tier. It is not intentional for every browser-served page, which
is what it amounts to in combination with the early return.

## Correction to the change's claim

`restore-links-on-pre-rendered-tiers` asserted that `other_pages` becomes
reachable on the hard-fetch population. **It does not, yet.** The change is a
necessary precondition — without `fc.links` no digest can be built at all — but
the digest gate makes it insufficient on its own. The proposal should not be
archived as if it delivered that outcome.

## Probe methodology note

Two probes in this session measured the wrong layer and nearly produced wrong
conclusions:

- `r.links == 0` on `FetchResponse` — that is the WIRE field, cleared by the
  `include_links` / `link_roles` filter at `fetcher.py:692`, not `fc.links`.
- an earlier synthetic fixture suggested `include_links` gates the structured
  link list. It does not; it only changes `content_md` rendering. Confirmed on
  real arXiv HTML: 484 links either way.

Both times the artifact under test was one layer off from the thing being
claimed. Worth naming, because both looked like clean evidence.
