# Findings — 2026-07-27 · `fix-routing-fence-and-jina-404-launder`

## Scope: TARGETED SUBSET, not a full matrix

**Do not read this as full-matrix evidence.** Per design D7 (quota-constrained),
this run tests ONE hypothesis on FOUR URLs:

> Does removing the next-links fence request from the router prompt (D1) degrade
> link discovery, now that `other_pages` must carry that need alone?

```
--mode detail --axis next_links
--slug hn-front --slug gh-trending
--slug hepsiburada-reviews-drilldown-on-page
--slug amazon-product-reviews-elsewhere
```

8 cells per side, versus 29 cases × 3 systems × 3 axes for the full run. Two
listing slugs (link-dense) and two affordance slugs (the class where the answer's
link lives on ANOTHER page — the `drilldown` kind of `other_pages` most at risk).

Quality and clarity axes were NOT judged. A regression outside these four URLs
would not be caught here. Provider: `claude-code-sdk` (subscription — ADR-0016;
never the metered API).

Artifacts: `eval/runs/before-fence-fix/`, `eval/runs/after-fence-fix/`.

## Result: no regression — but the bench axis did NOT test the changed path

**Correction.** The first read of this run was overstated. The `next_links` axis
scored `a2web_detail` only:

| metric | before | after | delta |
| --- | --- | --- | --- |
| `next_links` (a2web_detail) | 4 | 4 | 0 |
| contract pass (a2web_detail) | 4/4 | 4/4 | 0 |
| contract pass (a2web_extract) | 4/4 | 4/4 | 0 |
| envelope tokens (a2web_detail) | 2369 | 2369 | 0 |
| envelope tokens (a2web_extract) | 657 | 669 | +12 |

`A2WebDetail` calls `fetch(url)` **without** `ask=` — no LLM extraction, so
`request_routing` is never set. D1 only changes the ROUTING path. Worse, the axis
skips any system that emits no `next_links` block (`runner.py:398-410`), and the
routing path emits none by construction — so it silently scored zero cells on the
changed path while reporting a clean 4/4.

That is precisely the vacuous-guard shape CLAUDE.md warns about, reached while
verifying a fix for two vacuous guards.

### What actually establishes the result

**1. Proof, from the code: D1 cannot regress `next_links` on the routing path.**
`parsed_next_links` was ALREADY hard-set to `[]` in the routing branch before this
change (`git show main:…/extractor.py`, line 274). The fence was requested, emitted
by the model, and then discarded — never parsed into `next_links` on that path. It
only ever leaked into `answer`. Removing the request therefore loses no data that
was flowing; it removes data that was being thrown away after costing tokens.

**2. Direct measurement of `other_pages` on the routing path**, since the bench
would not do it. `fetch(url, ask=…)` on all four slugs, both arms:

| slug | `next_links` before → after | `other_pages` before → after |
| --- | --- | --- |
| hn-front | 10 → 10 (handler-sourced) | [] → [] |
| gh-trending | 10 → 10 (handler-sourced) | [] → [] |
| hepsiburada-drilldown | [] → [] | 1 drilldown → 1 drilldown |
| amazon-reviews-elsewhere | failed (walled) | failed (walled) |

**Link output is identical in both arms.** The `hn`/`gh` links come from the site
handlers (Tier 1, `fc.next_links_handler`), which D1 does not touch; the
hepsiburada drilldown comes from `routing.other_pages`, which survives unchanged.

Incidental gain: answers got **shorter** — 950→547, 579→321, 395→338 chars
(~40%) — consistent with no longer asking the model to emit a redundant block
that was discarded anyway.

## Incidental finding: `make bench` is broken on `main`

Not caused by this change, and it blocked the run until worked around.

```
$ make bench ARGS=...
LLM provider unavailable: unknown provider id: claude-code
```

The Makefile pins `A2WEB_BENCH_PROVIDER ?= claude-code`, but commit `ee2452c`
(*adopt `anyllm.ProviderName` + `resolve_provider`*) renamed the provider ids.
Valid values are now:

```
claude-code-cli · claude-code-sdk · anthropic-api · openai-compatible
```

So `make bench` fails for everyone on `main` with no working default. Both runs
here used `A2WEB_BENCH_PROVIDER=claude-code-sdk`.

**Severity: medium, not high.** ADR-0016's cost floor held exactly as designed —
the unresolvable id failed LOUD rather than silently falling through to metered
billing. No spend risk. But the ADR-0016 *default* is currently inoperative:
anyone running the bench must now supply a provider by hand, and the obvious
manual choice for someone unaware of the rename is `anthropic`, which is the
metered path the default exists to prevent.

Fix is one line in the Makefile (`claude-code` → `claude-code-sdk`). Deliberately
NOT bundled here — it is unrelated to both defects and belongs in its own change
with a test that pins the Makefile default to a member of `ProviderName`, so the
next rename cannot silently break it again. Filed in `BACKLOG.md`.
